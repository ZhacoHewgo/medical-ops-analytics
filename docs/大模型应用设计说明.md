# 医疗运营问数与报告设计

## 问数实现说明

问数走「词法解析 + 冻结指标目录 + 固定模板 SQL 计划 + 只读执行 + 交叉核验」：语句只由冻结模板生成，不接受任何自由 SQL。

- 解析（`backend/app/llm/nl2sql.py`）：从问句中提取统计期间（单日、日期区间、自然月、月份区间）、科室范围、是否按月展开、是否门诊人次自然月环比；其余文字只用于匹配指标名，不参与任何语句构造。
- 目录（`backend/app/llm/catalog.py`）：共 40 个指标，其中 6 个当期可计算（门诊人次、门诊人次环比、出院人次、平均住院日、住院次均费用、医疗收入总额），34 个明确标注缺口原因码（缺字段、口径未确认、字典未确认等）。缺口指标返回空值加原因码，不推算估值。
- SQL 计划（`nl2sql.generate_sql`）：意图先转成 `SqlPlan`——指标编码映射到唯一模板，模板固定表、固定列、固定聚合表达式与唯一 `WHERE` 结构；数据集、批次、构建号、起止日期、科室编码全部作为绑定参数（`%s`）传入，问句原文不进入语句。环比模板自动把可比基期并入查询窗口。
- 表白名单：模板只引用 `ads_outpatient_theme`、`ads_inpatient_theme`、`ads_income_theme` 三张认证 ADS 表，列取自 `SQL_TABLES` 登记集合。执行前统一走 `nl2sql.validate_sql`（内部即冻结注册表重建与逐字比对），校验语句、表、列、参数个数与参数格式；任一项不符即 422，伪造计划或改写语句都无法执行，`execute_plan` 与外部调用共用同一道闸门。
- 只读执行（`nl2sql.execute_plan`）：在只读一致性快照（`START TRANSACTION WITH CONSISTENT SNAPSHOT, READ ONLY`）内以绑定参数执行，会话级 `max_execution_time` 与 5 秒墙钟预算双重限时；连接失败、查询异常与超时统一降级 503。
- 交叉核验：模板 SQL 独立算出的数值必须与认证汇总逐点一致（金额按目录登记位数比对），不一致即降级 503，不返回两套数中的任意一套。
- 读取（`backend/app/llm/readers.py`）：认证汇总继续负责来源批次、缺失原因与覆盖/发布判定，未发布主题集市仍返回 503，科室范围、批次与数据源标识由服务端补齐。
- 输出统一为指标编码、单位、范围、图表类型、数据点、自然语言解释、缺失原因、数据源与批次标识；缺口指标的解释显式写明不可计算的原因。

### 模型意图入口

课程步骤把 `generate_sql()` 描述为「调用 LLM 生成候选 SQL」，`validate_sql(sql, user)` 要求校验只读、表白名单、语法并按角色注入数据权限；同一节点的具体要求是 SQL 100% 只读、引用表 100% 白名单、科室角色自动注入过滤、三要素齐全、50 问 ≥ 85%、超时降级不崩溃。当前实现按「模型只产出结构化意图、SQL 只由冻结模板产生」落地：

- 默认路径（未注入生成器）走本地词法解析与冻结模板，行为与前文一致，结果可重复；`SqlPlan.origin` 记为 `rules`。
- 注入路径（`generate_sql(question, user, generator=...)`、`run_nl_query(..., generator=...)`）：生成器收到 `candidate_prompt()` 组装的系统/指标/维度三层 Prompt，只返回 `indicator`、`start_date`、`end_date`、`scope`、`series`、`growth` 六个字段的 JSON。`parse_candidate` 拒绝非对象载荷、未登记字段（含 `sql`）、目录外指标、非法日期与非法科室值，随后与规则解析共用 `_seal_intent` 的目录与边界校验，再进入同一套冻结模板、绑定参数与 `validate_sql`。
- 降级：问句先接受指标与权限检查。模型超时、调用失败、返回非法载荷，或候选指标、日期、科室、粒度与规则校验不一致时，使用规则结果。成功响应的 `X-NL2SQL-Origin` 标记 `model`、`model-fallback` 或 `rules`，便于分别统计。
- 真实模型配置：FastAPI 进程设置 `LLM_API_BASE_URL`（如本地 `http://127.0.0.1:8091/v1`）和 `LLM_MODEL`，路由即调用兼容 `/chat/completions` 的服务。可选 `LLM_API_KEY` 从环境注入，`LLM_TIMEOUT_SECONDS` 默认 8 秒，最大 30 秒。远程 HTTPS 服务只收到由已校验指标、期间和科室重建的问题。未配置时沿用规则路径。


## 安全策略

- 问句仅解析为日期、科室和目录内指标。请求中出现 SQL 关键字、`patient_id`、身份证、联系方式等字样直接拒绝，不进入解析。
- 指标白名单与其他一切解耦：缺口指标不触库，未登记指标无法命中，命中多个指标时要求收窄问句。
- 科室范围由服务端按登录账号校验：科室账号只能查本科室，全院口径与跨科室编码一律拒绝；未绑定科室的科室账号拒绝。该校验在 `generate_sql` 内复用同一套逻辑，科室编码作为绑定参数传入，不拼接进语句。
- 显式科室参数不能覆盖登录身份：`generate_sql` 先按账号角色算出允许范围，再核对显式传入的科室；与允许范围冲突即 403，非科室角色仅在全院口径下可下钻到单一科室。科室编码格式不符返回 422。
- 参数边界：问句 1–300 字，单次最多 366 天，按月展开最多 24 个自然月，环比只接受完整自然月；越界返回 422。
- 模型调用有独立超时预算，失败时降级为规则。SQL 执行预算 5 秒，连同结果读取和对账共用 10 秒预算。超时、批次缺失、发布不完整或对账不一致时返回 503。
- 每次问数、报告与口径查询写入审计（资源、动作、范围、状态码），响应带 `Cache-Control: no-store`，不返回患者级明细。

## Prompt 模板

位于 `backend/app/llm/prompts.py` 的模板只约定结构化意图与缺失原因字段，日期、指标、白名单、科室范围与降级判断全部由应用侧独立完成。系统提示明确禁止输出 SQL 与患者字段，并逐字列出六个候选字段名。默认运行不调用任何外部模型或密钥，全部走本地规则，因此结果可重复、可审计。

## 评测集（50 题）

评测集位于 `backend/app/llm/eval/evalset.json`，由原 8 道门诊题扩展为 50 道跨主题题，覆盖门诊、住院、收入、药品、耗材、病种、资源效率、患者服务与安全边界九个主题。

- 题面结构：43 道可答（24 题覆盖全部 6 个可算指标，19 题覆盖 19 个缺口指标）、4 道越权、2 道无效问句、1 道可比基期超出覆盖（503）。每题标注角色、期望状态、指标编码、单位、图表类型与缺失原因。
- 期望值不写死：`backend/app/llm/eval/oracle.py` 用同一批合成种子行独立复算数值（人次、出院人次、平均住院日、次均费用、收入及环比），题面不保存任何数值常量；改动种子行时期望值随之变化，测试用探针验证这一点，避免「写死全通过」。
- 缺口题只允许空值：凡标注 `expect_null` 的题目，出现任何数值即判失败；原因码必须与目录登记一致。
- 载荷校验（`backend/app/llm/eval/eval.py`）：除数值外还核对指标编码、单位、图表类型、缺失原因、科室范围与解释非空，并检查响应中不出现患者标识字段。
- 判定：按主题汇总正确率，阈值 0.85（`threshold` 字段），未达阈值整体判失败；失败用例带具体字段差异，便于定位。
- 运行方式：题面解析、`generate_sql` 计划与白名单校验、显式科室与角色冲突、`validate_sql`、模型候选意图的封存与降级、伪造计划拒绝、绑定参数、只读快照、超时与交叉核验都在 `backend/tests/test_qa_query.py` 中离线执行；端到端 50 题需 `hospital_test` 隔离库与合成批次。
- 发布前置：住院与收入题读的是主题集市，评测前必须用 `aggregate_dws.rerun((起,止), themes=("inpatient","income"))` 一并发布；只跑默认 `themes=()` 时门诊 ADS 有数、两个主题集市为空，读取端按 `N10_ADS_NOT_PUBLISHED` 返回 503，评测会如实计为错误。预期不得为迁就未发布状态改成 503。

## 缺口与待验证

- 缺正式输入的指标继续按目录返回原因码。课程样例的床位使用率和药占比沿用已明确的课程计算口径。
- 端到端已在独立隔离 MySQL（`hospital_test`，本地一次性实例，合成批次）实跑：`backend/tests/test_qa_query.py` 与 `backend/tests/test_llm_reports.py` 共 45 项全部通过、无跳过、无失败，其中 50 题评测 50/50 且无失败用例；住院与收入 14 题由未发布时的 503 转为有值，数值与 `oracle.py` 独立复算逐项一致，未发布主题集市时仍如实返回 503。跑完确认主题表、状态表、DWS/ADS 与指标结果表残留均为 0 行。
- 2026-11-23 本地 Qwen2.5-3B-Instruct 与隔离 MySQL 课程数据复测：原题型映射到 2025 年 4–5 月及课程科室，数值由课程 CSV 独立复算。50/50 达标，28 题采纳模型意图，15 题用规则降级，7 题返回预期拒绝或不可查状态。另对模型 HTTP 请求施加实际超时，规则降级返回正确数值。该准确率覆盖整个问数链路，平台远程环境仍待复测。
